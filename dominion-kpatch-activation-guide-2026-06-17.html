What is kpatch? kpatch is Red Hat's implementation of live kernel patching — applying security fixes to the running Linux kernel in memory, without a reboot or maintenance window. The kernel keeps running; processes keep running; nothing notices except the CVE, which is now patched. kpatch is included with all Red Hat Enterprise Linux subscriptions at no additional cost.

Three-Command Quick Start

Quick Start — Three Commands to Live Patching
$ sudo dnf install kpatch-dnf  # Install the kpatch dnf plugin (one-time)
$ sudo dnf kpatch auto  # Enable automatic live patching
$ sudo kpatch list  # Verify which patches are loaded
Requires: active Red Hat subscription, RHEL 7.7+, x86_64 architecture. Run as root or with sudo.
That's it for most hosts. If your subscription is current and your kernel version has patches available, those three commands are the complete activation sequence. The detailed steps below are for environments that need version checks, troubleshooting, or fleet-scale deployment.

Full Step-by-Step Enablement

  1. Verify your RHEL version and kernel
    Confirm you are running a supported RHEL version (7.7+, 8.x, or 9.x) and record your current kernel version. kpatch patches are kernel-version-specific — you need to know exactly what you're running.
    $ cat /etc/redhat-release
    Red Hat Enterprise Linux release 9.4 (Plow)
    $ uname -r
    5.14.0-427.26.1.el9_4.x86_64
    $ subscription-manager status
    Overall Status: Current
    Expected: RHEL 8.x or 9.x, kernel version in the 5.14.0-427.x (RHEL 9.4) or 4.18.0-xxx (RHEL 8.x) range. Subscription status must show Current — kpatch patches are gated behind an active subscription.
  2. Install the kpatch-dnf plugin (one-time)
    The kpatch-dnf package adds a kpatch subcommand to dnf, which handles finding the correct patch packages for your running kernel version automatically. Install it once per host.
    $ sudo dnf install kpatch-dnf
    Updating Subscription Management repositories.
    Last metadata expiration check: ...
    Dependencies resolved.
    Installing: kpatch-dnf noarch 0.4-3.el9 rhel-9-for-x86_64-baseos-rpms
    Complete!
    Expected: dnf resolves and installs kpatch-dnf from the Red Hat BaseOS repository. If the package is not found, verify your subscription is attached and that the BaseOS repository is enabled: subscription-manager repos --list-enabled
  3. Enable automatic live patching
    This command queries the Red Hat kpatch catalog for your exact kernel version, downloads the appropriate patch package(s), and loads them directly into the running kernel. No reboot. No maintenance window. The kernel continues to serve workloads throughout.
    $ sudo dnf kpatch auto
    Fetching kpatch packages for kernel 5.14.0-427.26.1.el9_4.x86_64...
    Installing: kpatch-patch-5_14_0-427_26_1 x86_64 1-2.el9_4
    Running scriptlet: kpatch-patch-5_14_0-427_26_1...
    loading patch module: kpatch-patch-5_14_0-427_26_1.ko
    Complete!
    Expected: dnf finds one or more kpatch-patch-* packages matching your kernel version, installs them, and the installation scriptlet loads the patch module into the running kernel immediately. If the output says "nothing to do" or shows no patch packages, see the Troubleshooting section.
  4. Verify patches are loaded
    The kpatch list command shows all currently loaded kernel patches. Run this immediately after enablement and again after any future patch update to confirm active protection.
    $ sudo kpatch list
    Loaded patch modules:
    kpatch-patch-5_14_0-427_26_1 [enabled]
    Installed patch modules:
    kpatch-patch-5_14_0-427_26_1 [enabled]
    Expected output fields:
    FieldValueMeaning
    Loaded patch modules one or more entries Patches currently active in the running kernel
    Installed patch modules same entries Patches installed on disk (will reload after reboot)
    [enabled] enabled Patch is active and protecting the kernel right now
    [disabled] disabled Patch installed but not active — see troubleshooting
    (empty output) nothing listed No patches loaded — check subscription and kernel version
  5. Enable persistence across reboots
    The kpatch systemd service ensures that installed patch modules are reloaded after any future kernel restart. Enable it now so that your protection persists even if the system is rebooted for non-kernel reasons (hardware maintenance, power events, etc.).
    $ sudo systemctl enable --now kpatch
    Created symlink /etc/systemd/system/multi-user.target.wants/kpatch.service
    $ sudo systemctl status kpatch
    ● kpatch.service - Apply kpatch kernel patches
    Loaded: loaded (/usr/lib/systemd/system/kpatch.service; enabled; ...)
    Active: active (exited) since ...
    Expected: Service shows active (exited) — this is correct for kpatch. It runs at boot to load patches, then exits. The patches remain active in the kernel. enabled in the Loaded line confirms persistence across reboots.
    Note on kernel updates: If the kernel itself is updated (e.g., via dnf update kernel) and the system reboots to the new kernel, you must run sudo dnf kpatch auto again on the new kernel version to re-apply live patches. The kpatch catalog will have patches for the new kernel once Red Hat publishes them.

Supported RHEL Versions

RHEL Version kpatch Support Notes
RHEL 9.x Fully supported Preferred. Full kpatch catalog. Latest CVE patches released here first.
RHEL 8.x Fully supported Full catalog. kpatch patches available for 8.6 through latest 8.x EUS releases.
RHEL 8.8 specifically Confirmed — Dirty Frag patches available CVE-2026-43284, CVE-2026-46300 (RHSB-2026-003) kpatch confirmed for 8.8.
RHEL 7.7+ Supported (Extended Life) kpatch available but catalog coverage narrower than RHEL 8/9. Migrate to RHEL 9 for full coverage.
RHEL 7.0–7.6 Limited Older kernels — reduced catalog. Strongly recommended to update to 7.7+ or migrate to RHEL 8/9.
RHEL 6.x End of Extended Life — not supported No kpatch support. Migrate immediately — RHEL 6 receives no security patches of any kind.
ARM / aarch64 Not generally supported x86_64 required for full kpatch coverage. ARM/aarch64 kernel module loading is not supported. Verify with Red Hat before attempting deployment on ARM nodes.
x86_64 Full catalog — all supported RHEL 8/9 Primary architecture. Complete CVE patch coverage.

Troubleshooting

kpatch list shows nothing / empty output
Check 1 — Subscription:
subscription-manager status
Must show Current. If expired or unattached, patches will not download.

Check 2 — Kernel version in catalog:
sudo dnf kpatch check
If output is empty, no patches exist yet for your exact kernel version. Check the Red Hat Security Advisories page or pin the kernel to a version with known patches (RHEL 9.4: 5.14.0-427.x).
dnf kpatch auto says "nothing to do"
Possible causes:
  • Patches for this kernel version not yet published
  • All available patches already installed (run kpatch list to confirm)
  • BaseOS/AppStream repos disabled
Verify repos: subscription-manager repos --list-enabled | grep baseos
Patch shows [disabled] in kpatch list
A patch module is installed but not active. Manually load it:
sudo kpatch load /usr/lib/kpatch/$(uname -r)/

If the load fails with a module error, the patch may not be compatible with your exact running kernel build. Check that uname -r matches the patch package name exactly.
subscription-manager status not Current
Re-register and attach:
sudo subscription-manager register --auto-attach

If in a managed environment (Satellite):
sudo subscription-manager register --org=<org> --activationkey=<key>

Contact your Red Hat SA for activation key assistance.
kpatch-dnf package not found in dnf
Enable the correct repo:
subscription-manager repos --enable rhel-9-for-x86_64-baseos-rpms
(Replace 9 with your RHEL major version.)

Then retry: sudo dnf install kpatch-dnf
System rebooted — patches gone
If kpatch systemd service is not enabled, patches don't survive reboot:
sudo systemctl enable --now kpatch

If the kernel was updated before reboot, re-run:
sudo dnf kpatch auto
to apply patches for the new kernel version.

Deploying at Scale

Fleet Deployment — Red Hat Automation Stack

The three-command activation above works for individual hosts. For a fleet of dozens or hundreds of RHEL hosts — such as across Dominion's generation control, EMS, and SCADA infrastructure — use the Red Hat automation stack to deploy kpatch centrally with no per-host login required.

Red Hat Ansible Automation Platform provides a ready-made fleet deployment playbook that runs dnf kpatch auto and validates kpatch list across all target hosts in parallel. Your Red Hat SA can provide this playbook directly.

Red Hat Satellite manages kpatch content views — pin approved patch versions per environment tier (dev / staging / production), enforce patch SLAs, and track which hosts have patches applied vs. pending.

Red Hat Insights provides a live dashboard of patch compliance across your entire fleet — which hosts are patched, which CVEs remain open, and which hosts have active kpatch modules loaded. No agent required beyond the built-in insights-client included with RHEL.
