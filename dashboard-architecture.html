Red Hat OpenShift × SAP

How the Dashboard Works

Real-time event ingestion, processing, and visualization
on Red Hat OpenShift — the same pattern at any scale.

Every event tells a story. The dashboard makes it visible.

In a physical building, hundreds of systems generate events every second — badge readers authenticate employees, door sensors track movement, HVAC systems report conditions, safety systems watch for anomalies. These events are structured as CloudEvents — an open, vendor-neutral standard — and streamed to Red Hat OpenShift for processing.

The platform ingests, classifies, and persists each event, then pushes updates to the dashboard in real time using Server-Sent Events (SSE) — no polling, no page refreshes. What you see on screen is what's happening right now.

In the demo, your phone plays the role of an edge device — generating the same CloudEvent payloads that a real badge reader or door sensor would produce. The dashboard doesn't know the difference. That's the point. The same platform that runs a conference demo runs a production facility.

The integration path to SAP is identical — CloudEvents flow north through SAP Edge Integration Cell (deployed inside the same OpenShift cluster) into SAP Integration Suite, S/4HANA, and Analytics Cloud. Same events. Same platform. Different destination.
