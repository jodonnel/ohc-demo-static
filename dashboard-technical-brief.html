Edge-to-Core Event Architecture

How the demo captures, transports, processes, and visualizes
real-time events from edge devices through Red Hat OpenShift.

Event Protocol

Every device — physical or simulated — emits structured events conforming to the CNCF CloudEvents specification. Each event carries a type, source, timestamp, and domain-specific payload. The platform doesn't care where the event came from. It cares what it says.

Platform Flow

Events arrive at the ingest endpoint via HTTPS POST. The platform validates the CloudEvent envelope, classifies the event by type, and routes it to the processing layer. Processed events are persisted to a Persistent Volume (cloud-native block storage — gp3-csi on AWS, managed-csi on Azure) so state survives pod restarts.

The dashboard connects via Server-Sent Events (SSE) — a one-way, persistent HTTP connection. The platform pushes every processed event to all connected dashboards in real time. No polling. No WebSocket complexity. The browser opens a connection and listens.

SAP Integration Path

The same CloudEvents that power the dashboard can flow through SAP Edge Integration Cell — deployed inside the same OpenShift cluster — into SAP Integration Suite and from there to S/4HANA and SAP Analytics Cloud. The integration is architectural, not bolted on. Same events. Same platform. EIC is validated on both ROSA and ARO.
