March Madness Bracket Architecture

How live ESPN and NCAA.com data flows through Red Hat OpenShift
to power a real-time tournament bracket on GitHub Pages.

API Endpoints

The backend proxy running on Red Hat OpenShift exposes a clean REST API that the bracket app consumes. Each endpoint caches upstream data to protect against rate limits and provide consistent low-latency responses.

EndpointSourceCache TTLReturns
/api/bracketNCAA.com120sSeeds, regions, game results by round

/api/eventsInternal—SSE stream: score changes pushed in real time

Data Flow

A background thread polls ESPN and NCAA.com every 30 seconds. When scores change, the platform pushes updates to all connected browsers via Server-Sent Events (SSE) — a one-way, persistent HTTP connection. No polling from the browser. No WebSocket complexity. The bracket app opens a connection and listens.

The frontend works fully standalone on GitHub Pages — bracket picks, team selection, and navigation all function without the backend. Live scores and news are progressive enhancements that activate when the OpenShift backend is available.

SAP Integration Path

The same event-driven pattern powers enterprise integrations. Replace ESPN scores with IoT sensor data, badge taps, or supply chain events — the architecture is identical. SAP Edge Integration Cell, deployed inside the same OpenShift cluster, routes events to SAP Integration Suite, S/4HANA, and SAP Analytics Cloud.
