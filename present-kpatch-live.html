Overview

Live kernel patching — included in RHEL

  • kpatch applies critical kernel security fixes without rebooting the system
  • Ships with every Red Hat Enterprise Linux subscription — no additional purchase
  • Patches are applied in running kernel memory using ftrace-based function replacement
  • When you eventually reboot on your normal schedule, the permanent fix is in the updated kernel package
This is not a workaround. It is a supported, production-grade remediation path for kernel CVEs.
"kpatch is live kernel patching. It's included in your RHEL subscription. It applies kernel security fixes in memory — no reboot required. When you do reboot on your normal schedule, the permanent fix is waiting in the updated kernel package."
Emphasize: included in subscription. Not an add-on. Not a third-party tool.

Honest assessment

Pros and limitations

Advantages

  • Zero downtime for critical kernel CVE remediation
  • Compliance continuity — meet patch SLAs without maintenance windows
  • Immediate response to actively exploited vulnerabilities
  • No application restart — only the kernel is patched
  • Included in RHEL subscription

Limitations

  • Not all kernel patches qualify — only security-critical fixes
  • Cumulative: each live patch builds on the last. Eventually, a planned reboot consolidates them
  • Supported on RHEL 7.7+, 8, 9 — specific kernel versions only
  • Does not replace a reboot strategy — it extends the window between reboots
  • Cannot patch data structure changes — only function-level fixes
"I want to be honest about what kpatch does and doesn't do. It's not a replacement for rebooting — it's a way to extend the window between reboots. The patches are cumulative, so eventually you consolidate with a planned reboot on your schedule. But for critical CVEs — the ones being actively exploited — it gives you immediate protection without downtime."
LANDMINE: Don't oversell. If someone asks 'can we never reboot?' the answer is no. kpatch buys you time. It does not eliminate reboots.

LIVE DEMO

Three commands. No reboot.

  • sudo dnf install kpatch-dnf
  • sudo dnf kpatch auto
  • sudo kpatch list

That's it. The kernel is patched in memory. When you reboot on your normal schedule, the permanent fix is in the updated kernel package.
